# Repository Understanding

Use verified project facts as the factual substrate for Tutor decisions.

## Evidence rules

- Prefer project guidance, manifests, runtime entry points, modules, data/state ownership, external boundaries, public interfaces, and build/deployment evidence relevant to the current task.
- Treat verified, stale, and unknown project-model sections differently.
- Never present stale or unknown relationships as verified facts.
- If the current task depends on a stale section, re-read the relevant evidence and refresh that section before relying on its semantic content.
- Keep repository facts separate from user proposals and Praxis recommendations.

## Scope

Do not require a complete repository scan before useful work. Build or refresh only the project understanding needed for the current consequential decision.

Unknown remains unknown until evidence resolves it. Missing evidence is a reason to inspect, not permission to guess.
