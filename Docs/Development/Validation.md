# Validation

## Baseline

Python 3.10 is the minimum supported Python version. The neutral core uses only the standard library in V1.

GitHub Actions is the CI source of truth for repository validation once `.github/workflows/ci.yml` is present. The Python matrix also builds an isolated wheel from `pyproject.toml`, which validates the Git/pip CLI installation path on Python 3.10 and 3.13.

## Local checks

The current baseline is:

```bash
python -m unittest discover -s tests -v
python -m compileall -q praxis tests
python -m pip wheel --no-deps . -w /tmp/praxis-wheel
pnpm typecheck
pnpm test:dsh
```

## Codex package validation

```bash
python -m unittest \
  tests.test_codex_plugin_manifest \
  tests.test_codex_hooks_manifest \
  tests.test_codex_context \
  tests.test_codex_recovery \

```

The **Codex package** GitHub Actions job verifies portable/compatibility manifests, lifecycle hook declarations, adapter activation/recovery/fallback behavior, the 3000-character context bound, transcript/prompt independence, and the Codex-to-neutral-core dependency boundary.

This repository validation does not claim that a user's Codex environment has trusted or deployed the hook scripts. Live-host hook execution remains dependent on Codex installation/runtime policy.

From a checkout, refresh the installed Praxis plugin with:

```bash
./scripts/reload-codex-plugin.sh
```

The script refreshes the configured `praxis` marketplace and reinstalls `praxis@praxis`. It uses `codex` from `PATH` or finds the CLI bundled in ChatGPT.app under `/Applications` or `~/Applications` on macOS. Set `CODEX_BIN` to override the executable path. Open a new chat afterward; restart the app if the skill is still missing. Package refresh does not reload the current chat or enable Praxis in the project.

## Cursor / CodeBuddy plugins

Feature-07 validates both plugin packages against their current documented host contracts without requiring marketplace publication.

```bash
python -m unittest \
  tests.test_shared_recovery_hook \
  tests.test_cursor_integration \
  tests.test_codebuddy_integration \
  tests.test_agent_plugin_distribution \
  tests.test_command_surfaces -v
python -m compileall -q plugins/shared plugins/cursor plugins/codebuddy
```

The **Cursor / CodeBuddy plugins** GitHub Actions job runs these checks on Python 3.10.

Cursor supports automatic recovery context at session start. Its current native `beforeSubmitPrompt` output does not inject additional agent context, so Praxis uses that hook to refresh durable/project freshness only; it **does not inject** per-prompt recovery context on that path. The shared Praxis Skill and CLI remain available on demand.

CodeBuddy supports `additionalContext` on both `SessionStart` and `UserPromptSubmit`, so Praxis refreshes and injects recovery context on both lifecycle edges.

Both adapters reuse `praxis recovery-status`, cap automatic context at 3000 characters, ignore prompt/transcript text as approval evidence, and add no MCP server or MCP configuration.

## Activation delivery diagnostics

From the source checkout:

```bash
python3 -m praxis doctor --cwd .
```

With a separately installed CLI, inspect the installed plugin rather than assuming it matches source:

```bash
praxis doctor --cwd . --plugin-root /absolute/path/to/installed/praxis
praxis enable --cwd . --agents-fallback
praxis agents-fallback --cwd . --remove
```

Doctor reports project activation and fallback independently of script/configuration errors. It never changes host trust, refreshes project facts, or records its synthetic probe as a host invocation. Normal hook records under `.praxis/hook-observations.json` prove only that the script ran and emitted context; manual execution cannot prove host scheduling or model delivery. No record means not observed, not proof that an older script never ran. Python 3.10 reports TOML inspection unavailable; Python 3.11+ can inspect selected plugin/trust clues without exposing unrelated configuration.

### Live-host acceptance — Pending

Use a disposable project and the actual installed plugin. Do not pass a hook trust bypass flag or simulate a call to establish host acceptance.

1. Enable Praxis with the fallback announcement; review/trust its current hooks in the host. Start a new chat and request “Add a splash animation” without mentioning Praxis.
2. Inspect the actual host's hook result/context evidence and new SessionStart/UserPromptSubmit observations. Check that the agent loads the Tutor Skill before proposing a solution or editing and uses the agreed node format.
3. Answer only a style preference such as “quiet and minimal.” Check that this is not treated as architecture selection or implementation delegation. Once a scope is selected and delegated, mechanical work must proceed without repeated approval.
4. Pause, start another chat, and confirm tutoring remains inactive despite the AGENTS block. Resume explicitly and repeat the request.
5. Compact/resume the chat and verify that activation is delivered again, while open choices remain open and prior user reasoning/delegation are not fabricated.
6. In an untrusted/unsupported-hook environment, repeat through the AGENTS fallback and verify that live status controls activation. Remove the block and check surrounding instructions remain intact.

Record host/version, scenario, event/time, and observed behavior. Script probes, unit tests, or missing observations alone do not establish model receipt. Until these actions are actually observed, live-host acceptance is Pending.

## Green definition

A failed or unrun check cannot be reported Green. Mark unavailable or unrun validation as Pending and state the limitation. Source review or agent confidence is not a substitute for execution evidence.

### Codex hook discovery compatibility (2026-10-06)

Observed with the bundled Codex Desktop 0.160.0 app-server, using a disposable `CODEX_HOME` with only the Praxis marketplace/cache: `hooks/list` returned zero Praxis hooks for the installed manifest. Removing only root `plugin.json`'s Agent Plugins `$schema` returned both `SessionStart` and `UserPromptSubmit` as untrusted. Restoring the schema returned zero again. This verifies discovery, not execution or model receipt. The installed cache manifest was also corrected (original saved under `/tmp/praxis-installed-plugin-before-hook-fix.json`); a probe against the real home configuration then returned both hooks as untrusted. The user must review hook trust in the host before live Tutor acceptance can pass.
